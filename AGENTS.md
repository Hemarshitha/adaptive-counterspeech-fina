# Codex repository instructions — Adaptive Counterspeech Final Project

Read `PROJECT_SPEC.md` first. When present, also read `PROJECT_STATUS.md` and `docs/PROJ_2.pdf` before substantive changes.

## Non-negotiable constraints
- This is a **greenfield build from scratch** in a **new repository**.
- Do **not** copy, fork, import, adapt, or reuse source code, existing models, datasets generated by the previous implementation, experiment logs, or tests from `Hemarshitha/counterspeech_pipeline` or the mid-review presentation. Those are historical context only.
- Official academic scope follows `PROJ_2.pdf`. Only consult `pp_2_2_signed.pdf` when consistent with the original proposal. Do not treat `claude.pdf` as a requirement.
- Ship three interoperable pieces: YouTube-first human-in-the-loop browser extension; independent internal-research dashboard; shared backend AI pipeline with real event traces.
- Language scope: English, Hindi, Malayalam, Hinglish, Minglish, including transliteration/code mixing and language switching across turns.
- Preserve the primary research features: candidate-specific reaction prediction, multi-candidate generation, adaptive refinement, multi-turn context/escalation tracking, multilingual capability, independent evaluation against a newly implemented single-shot baseline.
- Never automatically publish counterspeech to online platforms; allow human edit/copy/manual posting.
- No API keys in frontend/extension, no made-up evaluation metrics, no fabricated reaction probabilities masquerading as calibrated predictions, no fake 'live' model calls.
- Separate real human messages from simulated reactions, and distinguish recorded model outputs from claims about actual human behavior.
- Do not disclose raw hidden model reasoning; provide auditable structured decisions/scores instead.

## Engineering workflow
- Follow a plan and phase gates; keep services modular and independently testable.
- Run automated tests and report what passed, failed, or could not be run. Never mark features complete solely because source files exist.
- Maintain `PROJECT_STATUS.md` with current scope, completed work, test commands/results, known limitations, and next steps.
- Before changing the requirements or adopting another source of truth, request user confirmation.
- When a user asks for planning only, do not write application code.
